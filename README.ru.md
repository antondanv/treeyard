## Что это и чем полезно

Ты уже работаешь с Claude Code или Codex, и правила проекта лежат в `AGENTS.md` или
`CLAUDE.md`. И всё равно знаешь, как это бывает. Код пишется за вечер, а проект месяц
«почти готов». План разросся в файл на тысячи строк, и агент перечитывает его в каждой
сессии. Просишь одно — получаешь ещё три вещи «заодно». Агент пишет «готово», а оно не
работает. А через неделю уже не вспомнить, на чём остановился.

Treeyard кладёт весь проект в одно дерево на экране: наверху цель, под ней вехи, под ними
задачи. Всё это — узлы дерева. По дереву ты проектируешь, из его узлов запускаешь агентов,
и по нему видно, что готово, что в работе и где всё встало.

### «У меня уже есть AGENTS.md и CLAUDE.md»

Они остаются, и это хорошо: в них правила — стек, команды, стиль. Но правила одинаковы для
любой задачи и ничего не говорят о том, где проект сейчас. Поэтому рядом обычно появляется
`PLAN.md` или `ROADMAP.md`, и с ним начинаются проблемы:

- он растёт на тысячи строк, и агент читает его целиком в каждой сессии: уходят токены,
  размываются инструкции;
- галочки в нём агент ставит себе сам, и «готово» там не значит «работает»;
- два агента правят один файл и не знают друг о друге;
- твои собственные шаги и всё, что ждёт сервера или оплаты, тонут среди пунктов.

Treeyard оставляет в `AGENTS.md` только правила, а план и состояние проекта переносит в
дерево. Каждая задача — отдельный файл со своим статусом и журналом, и агент получает
контекст одной своей задачи, а не весь план. При этом это всё те же Markdown-файлы в твоём
репозитории: они лежат в `.tree/` и коммитятся вместе с кодом.

### Есть идея, но непонятно, с чего начать

Открой пустую папку и запусти `treeyard`. Рассказывай как есть: сплошным текстом, не по
порядку. Агент задаёт вопросы и к каждому предлагает свой вариант ответа, ты поправляешь
и рассказываешь больше. Идея из головы превращается в план на экране: цель, первый
результат, который можно проверить в жизни, и задачи на пути к нему. В том числе те, что
агент за тебя не сделает: сервер, домен, оплата.

### Проект уже есть, и он большой

Запусти `treeyard` в папке проекта. Агент сам прочитает код, документы и историю и
расскажет, что нашёл: что на самом деле работает, что обещано и не сделано, где остались
хвосты. Потом задаст несколько вопросов и построит по проекту дерево. На нём видно, что
готово, что в работе и где ты упёрся в стену — с причиной и с условием, при котором можно
идти дальше. В любой момент агент проверит всё дерево и покажет, что застряло, что
разрослось и за что пора браться.

### Дальше ты видишь свой проект

Выбери задачу и открой на ней Claude Code или Codex — прямо рядом с деревом. Агент
начинает с контекстом именно этой задачи: зачем она нужна, что рядом, какие в проекте
правила. Весь план ему читать не нужно. Сделанное он не закрывает сам: показывает
доказательства, а принимаешь работу ты. Если агентов несколько, на дереве видно, кто
работает, а кто ждёт твоего ответа. Вернулся через неделю — у каждой задачи свой журнал,
а отдельный список показывает всё, за что можно взяться прямо сейчас.

Это и есть Agent-Driven Development: ты проектируешь, агенты разрабатывают, а ты
управляешь проектом и принимаешь работу.

## Практики вайбкодинга, которые уже внутри

Treeyard не просто показывает задачи. В него встроены правила, которые экономят токены и
время и поднимают качество. Следить за ними самому не нужно: так устроен сам инструмент.

| Что делает Treeyard | Что это даёт |
| --- | --- |
| Агент получает контекст только своей задачи | Сессия стартует примерно с 3 тыс. токенов вместо 65 тыс. на весь план, и короткие инструкции агент не теряет |
| Одна задача — одна сессия | Агент доводит задачу до конца, пока контекст свежий; нет бесконечного «ещё чуть-чуть» |
| Сначала план, потом код | Ошибка ловится в плане, а не в уже написанном коде |
| Агент не ставит «готово» сам, а показывает доказательства | Меньше «готово, а не работает»: есть команда с выводом, скриншот, коммиты |
| Новая идея — отдельная задача, а не «заодно» | Токены и время идут на то, что ты просил, а идеи не теряются |
| История — в журнале задачи, решения — в одном месте с причинами | Новая сессия не перечитывает лог на тысячи строк, а что решили и почему — записано один раз |
| Цель из жизни, твои шаги в плане, статус «ждёт» | Проект не встаёт на сервере, домене и оплате: их видно с первого дня, а работа идёт в других ветках |

Правила собраны из моих проектов и из чужих практик, проверенных годами: Mikado, Shape Up,
GTD, рекомендации Anthropic по Claude Code. Все двенадцать — на одной странице:
[docs/practice.ru.md](docs/practice.ru.md).

## Зачем я это сделал

Treeyard вырос из моего собственного опыта вайбкодинга. С агентами код пишется очень
быстро, но потом проект почти всегда встаёт. Обычно он упирается в то, что может сделать
только человек: арендовать сервер, купить домен, подключить оплату, показать продукт живым
людям. Пока до этого не доходят руки, агенты пилят побочные фичи, план разрастается в
журнал на тысячи строк, а каждая новая сессия начинает с того, что перечитывает его
целиком. В итоге код готов, а проект стоит.

В Treeyard я собрал практики, которые помогли моим проектам пройти эту точку. Так я веду
все свои проекты, включая сам Treeyard.

## В цифрах

- **Чтобы начать работу, агенту нужно примерно на 95% меньше токенов.** Сессия из узла
  стартует с контекстом около трёх тысяч токенов: от 2,6k до 4,0k, медиана 3,0k по семи
  узлам дерева этого репозитория. Если вместо этого отдать агенту весь план — все узлы с
  описаниями и журналами, — получится 65 тысяч токенов на том же дереве из 105 узлов, а
  вместе с `docs/` и README — 84 тысячи. Контекст узла меньше на 95–96%. Даже обзор всего
  дерева на одной странице (`treeyard show`, 5,5k) почти вдвое больше.
- **Экономия растёт вместе с деревом.** На свежем дереве из 12 узлов весь план (1,0k) ещё
  меньше контекста одного узла (1,7k), так что экономить пока нечего. К тому же основная
  часть токенов в сессии уходит на работу с кодом, а не на её старт.
- **Treeyard собран с помощью самого себя.** Он ведётся своим деревом с первого коммита:
  за пять дней — 108 коммитов, 41 узел готов и ещё 18 на проверке, 35 сессий агентов
  открыто из узлов (со 2 по 6 октября 2026 года).

<sub>Как считали токены (6 октября 2026 года): контекст узла выгружали командой `treeyard
context <id>` в файл и считали через `claude -p "/context" --system-prompt-file <файл>`,
то есть токенизатором самого Claude. Результат сверили с настоящим запросом: 3 387 токенов
против «3.4k». У Codex и Gemini свои токенизаторы, и числа у них будут другими.</sub>

## Когда стоит пользоваться, а когда нет

**Treeyard пригодится, если**

- проект живёт дольше одной сессии — дни, недели, месяцы;
- направлений работы несколько, и часть из них ждёт чего-то извне;
- часть работы можешь сделать только ты сам: сервер, домен, оплата, договор, показ живым
  людям;
- параллельно работают несколько агентов или разные CLI, и хочется видеть, кто чем занят;
- у тебя несколько проектов, и ты возвращаешься к одному из них после перерыва: дерево и
  журналы напомнят, на чём ты остановился.

**Лучше обойтись без него, если**

- задача одна и небольшая: написать скрипт, поправить баг, что-то выяснить. Проще открыть
  обычный `claude` или `codex` — на посадку дерева, критерии и статусы уйдёт больше
  времени, чем на саму задачу;
- это прототип на один вечер, который потом выбросят;
- команда уже живёт в своём трекере. Treeyard рассчитан на одного человека с агентами,
  хотя синхронизироваться с доской GitHub Project он умеет.

Сам Treeyard код не пишет — это делают твои агенты. Он хранит план, даёт каждому агенту
его задачу и показывает, где проект сейчас.

## Быстрый старт

Понадобится Node.js 22 или новее и хотя бы один CLI агента: Claude Code, Codex,
Antigravity или OpenCode. Чтобы сессии открывались в панелях рядом с деревом, нужен ещё
tmux (на macOS — `brew install tmux`). Основная платформа — macOS.

```sh
npm install -g @antondanv/treeyard
treeyard config lang ru                    # интерфейс, шаблоны и тексты для агентов — на русском
cd my-project && treeyard                  # если дерева ещё нет, откроется мастер посадки
```

По умолчанию интерфейс на английском, а команда `treeyard config lang ru` переключает его
на русский. Посадка дерева вместе с агентом занимает минут двадцать. Начать можно и
по-другому:

```sh
treeyard init                              # новое дерево: с агентом или по шаблону
treeyard init --agent --brain codex        # сразу с агентом, без мастера
treeyard import                            # агент сам прочитает план проекта и построит дерево
```

## Как с ним работать

1. Открой вкладку **«Сейчас»** (`2`): там всё, за что можно взяться прямо сейчас, по всем
   веткам. Выбери узел.
2. Нажми `c`, и рядом с деревом откроется сессия Claude Code по этому узлу. `⏎` открывает
   меню со всеми действиями, в том числе с запуском других агентов.
3. Агент получает контекст узла, изучает код и предлагает план. Ты его одобряешь, и агент
   берётся за работу.
4. Когда задача сделана, агент отправляет узел **на проверку** и прикладывает
   доказательства: команду с выводом, скриншот, свои коммиты (их можно посмотреть по `V`).
   Ты проверяешь и нажимаешь `d` — узел **готов**.
5. Если работа упёрлась во что-то внешнее, нажми `w`: узел перейдёт в **«ждёт»** с
   причиной и условием возврата, а ты займёшься другой веткой.
6. Если по ходу появилась идея, добавь её клавишей `a` со статусом «идея». Раз в неделю
   загляни во вкладку **«Ждёт»** (`3`) и проверь, не пора ли к чему-то вернуться.

## Разработка

```sh
git clone https://github.com/antondanv/treeyard && cd treeyard
npm install                     # при NODE_ENV=production: npm install --include=dev
npm run build && npm link       # команда treeyard из dist/
npm run dev -- <args>           # treeyard прямо из исходников (tsx)
npm run typecheck && npm test && npm run lint && npm run build
npm run screenshots             # переснять картинки README на английском и русском (нужен Chrome)
FORCE_COLOR=2 npx tsx scripts/screenshot.ts ../my-app shot.png 130x36   # PNG интерфейса
```

Сессии, панели и модели работают через [Brainyard](https://github.com/antondanv/brainyard)
(`@antondanv/brainyard`) — единый слой для всех CLI агентов.
