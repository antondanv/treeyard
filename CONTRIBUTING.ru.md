# Как участвовать в Treeyard

[English](CONTRIBUTING.md) · **Русский**

Treeyard делает один человек. Issues и pull requests приветствуются, по-русски или
по-английски. Здесь — как собрать и проверить проект, как называть ветки и коммиты, что
писать в pull request и issue и что делать с папкой `.tree/`.

## Прежде чем начать

- Маленькую правку — опечатку, очевидный баг, недостающий тест — можно сразу присылать
  pull request'ом.
- Новая возможность, другое поведение или клавиши, новая зависимость: сначала откройте
  issue и опишите задачу, которую это решает. У Treeyard есть направление
  ([docs/vision.md](docs/vision.md)), и не каждая хорошая идея в него ложится. Короткий
  разговор в issue сбережёт pull request, который не вольют.
- Сначала просмотрите [открытые issues](https://github.com/antondanv/treeyard/issues): баг
  может быть уже известен.

## Сборка и запуск

Нужны Node.js 22 или новее и git. tmux нужен для сессий в панелях и для тестов, которые
гоняют настоящий терминал; без него эти тесты пропускаются. Chrome нужен только для
скриншотов.

```sh
git clone https://github.com/<вы>/treeyard && cd treeyard
npm install                     # при NODE_ENV=production: npm install --include=dev
npm run dev -- <args>           # treeyard из исходников (tsx)
npm run build && npm link       # команда treeyard из dist/
```

Как устроен код — [docs/architecture.md](docs/architecture.md); что делает каждая клавиша
и команда — [docs/reference.ru.md](docs/reference.ru.md).

## Проверки

Прогоните их, прежде чем просить ревью. CI гоняет то же самое на Ubuntu и macOS, на Node 22
и 24:

```sh
npm run typecheck && npm test && npm run lint && npm run build
```

- `npm run format` правит формат и то, что Biome умеет исправить сам.
- `npm run test:watch` держит Vitest запущенным, пока вы работаете.
- Тесты читаются как русский интерфейс: `vitest.config.ts` задаёт `TREEYARD_LANG=ru`, поэтому
  ожидаемые строки в тестах — русские. Английский проверяется отдельно, в
  `test/i18n.test.ts`.
- Тесты не трогают ваш `~/.treeyard` (`TREEYARD_HOME` указывает на временную папку) и
  запускают tmux только на своём сокете. В новых тестах — так же.
- Сессии и панели руками пробуйте только на черновом дереве (`treeyard init` в пустой
  папке), никогда на проекте, который вам дорог. Тестовые панели закрывайте за собой.

## Что помнить в коде

- TypeScript в строгом режиме, ESM, Ink 7 и React 19. Комментарии по-английски, коротко и
  про «зачем», а не «что»; стиль — как в соседнем коде.
- Тексты интерфейса — через `t('Русский текст')`: русская строка — ключ, английская — в
  `src/i18n/en.ts`. Ключ без перевода роняет `test/i18n.test.ts`.
- Шаблон дерева есть на двух языках: `templates/*.yaml` и `templates/en/`. Правьте оба.
- Изменилось поведение, клавиши или настройки → поправьте `docs/reference.md` и
  `docs/reference.ru.md`. Изменился вид → `npm run screenshots`, чтобы переснять картинки
  README. README остаётся коротким; подробности — в справочнике.
- То, что видит человек, проверяйте в самом интерфейсе, а не только тестами: `npm run dev`
  в черновом дереве или PNG через
  `FORCE_COLOR=2 npx tsx scripts/screenshot.ts <папка-с-деревом> shot.png 130x36`. На узком
  терминале, около 100×30, тоже.
- Запуск CLI агентов, панели и сессии — это [Brainyard](https://github.com/antondanv/brainyard)
  (`@antondanv/brainyard`). Если правка нужна там, присылайте её туда, а не обходите в
  Treeyard.

## Ветки и коммиты

- Сделайте форк и ветку от `main`. Ветку называйте по смыслу: `fix/epipe-exit`,
  `feat/node-order`, `docs/reference-keys`. (Ветки вида `treeyard/<id>` — мейнтейнера:
  их создаёт treeyard для worktree узлов.)
- Сообщения коммитов — по [Conventional Commits](https://www.conventionalcommits.org/ru/),
  по-английски: `type(scope): что изменилось`. Типы, которые здесь в ходу: `feat`, `fix`,
  `test`, `docs`, `refactor`, `perf`, `chore`. Scope — какая часть Treeyard затронута, его
  можно опустить. Примеры из истории:

  ```
  feat(update): tell when a newer treeyard is in npm
  fix(package): add src/index.ts so the exports entry dist/index.js exists
  test(mouse): wait for the tree's keys before pressing a panel button
  ```

- Один коммит — одна правка. Коммиты pull request'а попадают в `main` как есть (его
  вливают merge-коммитом), поэтому коммиты «fix typo» и «review» вкладывайте в тот коммит,
  который они чинят.
- Ветку держите свежей через rebase на `main`, а не слиянием `main` в неё.
- Без строк-подписей и «generated with …» в коммитах и описаниях pull request'ов. Автор —
  git-пользователь, который сделал коммит.

## Pull requests

[Шаблон](.github/pull_request_template.md) спрашивает вот что; заполните то, что относится
к делу:

- что меняется и зачем, в нескольких предложениях, и какой issue это закрывает
  (`Fixes #12`);
- как вы это проверили: команды и их результат, а для видимого — скриншот интерфейса (на
  обоих языках, если менялся текст);
- что документация, `src/i18n/en.ts` и обе языковые версии шаблонов поправлены, где нужно;
- что в `.tree/` изменений нет (см. ниже).

Один pull request — одна правка: исправление бага и рефакторинг — два pull request'а.
Хотите раннего отклика — откройте его черновиком (draft). Перед ревью CI должен быть
зелёным. Разрешите правки мейнтейнерам (Allow edits by maintainers): мелочь проще дописать
в вашу ветку, чем гонять круг комментариев.

## Issues

- **Баг** — [форма](https://github.com/antondanv/treeyard/issues/new?template=bug_report.yml)
  спрашивает `treeyard --version`, `node --version`, ОС, терминал, `tmux -V` и CLI агента,
  если баг в сессии. Дальше: что вы делали, чего ждали, что случилось. Когда treeyard
  падает, он пишет отчёт в `~/.treeyard/crashes/` и показывает путь к нему; приложите его.
  В отчёте — команда и стек, там могут быть пути ваших проектов: просмотрите его сначала.
- **Идея** — [форма](https://github.com/antondanv/treeyard/issues/new?template=feature_request.yml)
  начинается с задачи: что вы делали и что помешало. Предложенное решение приветствуется,
  но задача важнее.
- Вопрос, как что-то работает, — сначала [docs/reference.ru.md](docs/reference.ru.md); если
  ответа там нет, откройте пустой issue.

## Дерево в `.tree/`

Treeyard разрабатывается в Treeyard. `.tree/` — рабочий план мейнтейнера: в `tree.md` —
цель, правила и решения, в `nodes/*.md` — узлы с критериями и журналами, в `README.md` —
обзор всего дерева. Оно коммитится вместе с кодом, отдельными коммитами
`chore(tree): …`, и меняется по нескольку раз в день.

**Не несите в pull request правки `.tree/`.** Чтобы участвовать, treeyard не нужен, и узел
под вашу правку не нужен: хватает issue и pull request'а, дерево мейнтейнер обновит сам.
Причина практическая: дерево меняется постоянно, поэтому pull request, который его трогает,
почти всегда конфликтует, а слияние на GitHub не запускает драйвер слияния, который
держит `.tree/README.md` согласованным.

Если запустить внутри клона `treeyard` или CLI агента, который читает `AGENTS.md`, они
запишут в это дерево. Перед push проверьте, что ваша ветка его не трогает:

```sh
git diff --stat main...HEAD -- .tree    # должно ничего не вывести
```

Если что-то вывелось, уберите эти изменения из своих коммитов. Попробовать treeyard на
своём дереве — посадите его в черновой папке.
