Из работы над Factoyard (узел k3w4, 05.11.2026). Сессия Claude Code вела направление и раздавала дочерние узлы агентам Sonnet по два сразу, через свой инструмент Agent. Такие агенты к узлам не привязаны: переписка живёт внутри сессии-координатора, и владелец не может открыть их из дерева, прочитать или продолжить. От узла остаются только журнал, коммиты и статус.

Готовое уже есть: treeyard open <id> --bg. Но координатору с ним не хватает трёх вещей:
- передать сессии своё задание сверх контекста узла: ограничения, соседние сессии в том же дереве, «не перезапускать завод», «без платных вызовов»;
- выбрать модель на запуск (сейчас model одна на проект в treeyard config);
- узнать, что сессия закончила, и получить её отчёт. Сейчас — только опрашивать статус узла и git log.

Что хочется: координатор запускает сессию по узлу командой с текстом задания и моделью. Сессия видна в узле, как любая другая. По концу или вопросу координатор получает уведомление и отчёт, а при нужде дописывает сессии следующую реплику.

Для этого, вероятно, понадобится связь между сессиями разных агентов от разных провайдеров (Claude Code, Codex, Antigravity, OpenCode): общий почтовый ящик, где можно отправить сообщение сессии или узлу и подождать, пока узел сменит статус или сессия закончит. Сейчас SendMessage у Claude Code работает только между его же сессиями. Естественное место для такого ящика — Brainyard, он уже держит панели и сессии всех CLI.

Попутно об экономии: продолжение старого агента заново читает всю его переписку. Поэтому на каждый узел нужна свежая сессия, а продолжить её должен уметь человек из узла.
