Координатор раздаёт узлы, «трогающие разные файлы», — проверять, а не угадывать. Как в exit-0-run/treeyard: узел заявляет пути (intents), open предупреждает о пересечении с открытыми узлами; пробное слияние веток открытых узлов попарно (git merge-tree --write-tree, без checkout) в wait и status — «узлы A и B столкнутся в файле X» до слияния. Вариант — аренда файлов на срок с pre-commit хуком, как в MCP Agent Mail.

Модуль src/agents/overlap.ts: для узлов с worktree в работе и на проверке читает файлы, закоммиченные веткой с тех пор, как она разошлась с веткой основной папки (HEAD...treeyard/<id>, changedFiles в worktree.ts), и незакоммиченные в их worktree (git status, с новыми файлами); .tree/ и файлы с одинаковым содержимым в обоих worktree не в счёт; влитая ветка ни с чем не пересекается. wait и queue печатают «A» и «B» правят один файл: путь (строка на файл, до пяти, остальное счётом; EN — «A» and «B» edit the same file: path); wait --json — поле conflicts ([{nodes:[{node,title,status}], files}]), queue --json — событие overlap. Читается раз в 15 с, пока ждёт, и перед ответом. Сессиям узлов в работе (узел на проверке не будится) уходит письмо через sendToNode — от treeyard, не от человека, с названием второго узла, файлами и treeyard send; один раз на пару и файл: файл-метка в .tree/.local/conflicts/ создаётся через wx (wait и queue вместе не пришлют дважды), письмо, не дошедшее ни до кого, метку снимает. Тесты на настоящем git: test/overlap.test.ts, 15 штук (коммиты и незакоммиченное, одинаковое содержимое, статусы и влитая ветка, ids, письма один раз, wait, queue, wait из shell с --json). npm run typecheck && npm test (98 файлов, 919 тестов) && npm run lint && npm run build — зелёные. Справка wait и queue на обоих языках в commands.ts, docs/reference.md и reference.ru.md, architecture.md, скилл treeyard-coordinate. Вживую на временном проекте с двумя worktree: treeyard wait A B --all печатает ⚠ «Бот» и «Сайт» правят один файл: app.txt (ru) и ⚠ «Бот» and «Сайт» edit the same file: app.txt (en), в --json — conflicts. Сценарий живой проверки координатором после слияния: 1) во временной копии проекта (git, два узла к работе) treeyard open A B --bg --worktree с заданием «правь в обоих src/x.ts»; 2) treeyard wait A B --timeout 10m — в ответе строка про общий файл; 3) treeyard show A --only mail и то же для B — по одному письму от treeyard про другой узел, в .tree/.local/conflicts/ — файл на пару и файл; 4) повторить wait — строка есть, новых писем нет; 5) перевести A в review — B всё равно получает письмо про новый общий файл, сессия A не просыпается; 6) влить ветку A — строка пропала. Осталось: узлы без worktree (в папке проекта) в пересечениях не видны; текстовый конфликт (merge-tree) не проверяется — только общий файл, а общие файлы вроде словаря переводов дадут строку каждой паре; wait не возвращается на новом пересечении — всё это заведено узлами-идеями.
