# Treeyard 0.2.0

*Черновик заметок к выпуску. Изменения с 0.1.1 (7 октября 2026).*

В 0.1.1 treeyard был деревом и пусковой кнопкой: сажаешь цели и открываешь из них сессии
агентов. В 0.2.0 одна сессия может раздать узлы другим, следить за ними и переписываться с
ними. У каждого узла может быть свой git worktree. Агенты узнают о дереве сами, а у каждой
команды, которую зовёт агент, теперь есть короткая форма, в которой трудно ошибиться.

[Обновление](#как-обновиться) — один `npm install`. Ниже — шаги, о которых стоит знать.

## Несколько сессий сразу

- **`treeyard wait`** ждёт, пока узел выйдет из «в работе» или его сессия закончит ход,
  остановится в ожидании тебя или завершится. Печатает статус, последнюю запись журнала и
  последнее сообщение сессии целиком (вопрос или итог) из стенограммы CLI. `--all` ждёт все
  узлы. Кончилось время — код выхода 124.
- **`treeyard send`** пишет сессии самого узла, а не открывает новую. Письмо сначала ложится
  в почтовый ящик проекта. Затем treeyard набирает его в свободной панели, будит уснувшую или
  продолжает фоновую сессию; занятой — доставит после конца хода. С `--wait` получаешь и
  ответ. `--answer` передаёт твой ответ в диалог с вопросом. `--approve` и `--reject` отвечают
  на запрос разрешения, и только с `--as ты`.
- **Письма посреди хода.** `treeyard hook claude|codex|antigravity|opencode install`
  доставляет ждущие письма вместе со следующим сообщением и между двумя вызовами
  инструментов. Занятой сессии не нужно сначала заканчивать ход.
- **Тормоз на пинг-понг.** После 6 писем подряд между двумя узлами без настоящей работы в
  промежутке следующее не уходит (`mail_limit`, `--force`).
- **`treeyard queue`** запускает узлы по очереди: открытых детей узла по порядку, не больше
  `--parallel` сразу. Узел с `needs` стартует, когда те узлы на проверке или готовы. Когда окно
  подписки дошло до `--limit` %, очередь ждёт сброса.
- **Пересечения.** `wait` и `queue` говорят, когда два узла в работе меняют один файл (по
  пробному слиянию в памяти), и один раз пишут об этом обеим сессиям.
- **`open` для нескольких узлов сразу**: `treeyard open a b c --pane` (или `--bg`), с `--task`
  — заданием поверх контекста узла и `--json` для программ.
- **`treeyard sleep`** усыпляет панель узла и сохраняет сессию на потом. **`treeyard peek`**
  показывает последние строки экрана панели, не подключаясь к ней.
- **`treeyard models`** — модели и уровни усилий каждого CLI. **`treeyard limits`** — окна
  подписки (по умолчанию свежие, `--offline` — только локальные снимки).
- Новый скилл **`treeyard-coordinate`** учит агента всему этому: выбрать узлы, которые
  трогают разные файлы, раздать их, дождаться, принять работу по дифу и проверкам, влить.

## Свой git worktree у узла

- `treeyard open <id> --worktree` (и форма запуска в TUI) открывает сессию любого CLI в своём
  worktree узла на ветке `treeyard/<id>`. Коммиты ветки — коммиты узла. Команды из worktree
  пишут основное дерево.
- `treeyard worktree` — список worktree, `add` и `setup` готовят его (команда `setup` проекта
  и `.worktreeinclude`), `rm <id>…` / `rm --done` убирает чистые и влитые.
- У `.tree/README.md` свой драйвер слияния: ветки, которые трогают разные узлы, сливаются без
  конфликтов в обзоре.

## Дерево знает больше, агенты набирают меньше

- **Контекст сессии из узла вдвое короче.** В нём узел, путь, соседи, журнал и правила
  проекта — всё, что напечатал бы `show`, так что агент больше не перечитывает свой узел. Как
  вести дерево, агент узнаёт один раз — из скилла; контекст на него ссылается и оставляет
  только факты сессии и правила, нарушение которых не отменишь. Где скилла нет (OpenCode), в
  контексте по-прежнему список команд. «Правила для агентов» в новых деревьях тоже ссылаются
  на скилл, а не пересказывают его.
- Агенты узнают о дереве сами. Скиллы `treeyard`, `treeyard-init` и `treeyard-coordinate`
  ставятся в Claude Code, Codex и Antigravity и обновляются с каждой новой версией treeyard,
  так что их знает и обычный `claude` или `codex`, запущенный в проекте. Выключить —
  `treeyard config skills off`.
- **`treeyard status`** показывает всю настройку в одном месте: версии, дерево, скиллы, блок в
  AGENTS.md, хуки, живые сессии, песочницу Codex. У каждой проблемы — команда, которая её
  исправит.
- Новые команды вместо пайпов и ручных правок: `find`, `show --brief` / `--journal N` /
  `--only` / `--status` / `--under`, `show` для нескольких узлов, `log --status --commit`
  (закрыть узел одной командой), `log --fix`, `set` для нескольких узлов, `set needs+=` /
  `needs-=`, `add --from-json`, `rm`, `decide`, `goal`, `rules`, `treeyard commit` (только
  файлы дерева), `image --note` к каждому файлу.
- Статусы в командах — словом на любом языке или алиасом (`review`, `на проверке`,
  `проверка`). Вне терминала у каждой строки дерева статус написан словом.
- **Хук коммитов** (`treeyard hook install`) сам привязывает коммиты сессии к её узлу и
  переводит их на другой узел, когда агент переходит к нему.
- Для программ: `show --json --all`, `treeyard watch` (строка на каждое изменение дерева),
  `treeyard docs`, `treeyard projects`, `open --json`, `sessions --json`.
- Обзор корня теперь находит готовых родителей, открытые узлы под закрытыми ветками, «на
  проверке» с незакоммиченным кодом, длинные названия, пропущенные сроки и ждущие узлы, у
  которых прошла дата возврата.

## В TUI

- **`c` — меню агентов.** Раньше `c` сразу запускал Claude Code, теперь открывает список CLI:
  сверху тот, что запускали последним, с его настройками, ниже остальные. `c` `⏎` повторяет
  последний запуск.
- **Сначала — последний запуск.** Меню узла помнит, как ты запускал каждый CLI (модель,
  усилие, старт, место, worktree), и `treeyard open` без флагов делает так же. `launch_memory`
  — своя память у проекта или общая.
- **Уведомление об обновлении.** Тост, `treeyard status` и `treeyard --version` говорят, что в
  npm вышел treeyard новее, и дают команду установки. npm спрашивается не чаще раза в день, в
  фоне. Выключить — `treeyard config updates off`.
- `Esc` отменяет зависшую задачу «разбить на шаги» или «сформулировать „готово, когда“», а
  тайм-аут останавливает её сам.
- Узел «в работе» без сессии и без записей дольше `stale_after` часов (по умолчанию 2)
  помечается «без сессии N ч».
- Шапка предупреждает, когда в AGENTS.md / CLAUDE.md нет блока о дереве или он устарел. `!`
  это исправляет.
- Перед первым запуском treeyard спрашивает, как запускать Codex (`codex_access`: песочница
  плюс treeyard и git или твой `config.toml`) и давать ли Antigravity полный доступ
  (`antigravity_access`).
- Ввод и прокрутка в панели агента откликаются быстрее, а дерево рисуется (реже) и без фокуса
  терминала.

## Исправления

- Падение, `SIGTERM` и `SIGHUP` возвращают терминал чистым и пишут ошибку в лог с версией.
  `treeyard show … | head` выходит тихо, а не падает на EPIPE.
- `add`, `set` и `HEAD` работают как надо из любого git worktree.
- Длинные письма доходят до панели кусками, которые принимает tmux 3.7. Панели и привязки
  сессий Antigravity находятся снова (одну привязку чинит руками
  `treeyard sessions <id> <старый> --replace <новый>`).
- `import` и `decide` сохраняют написанную руками шапку `tree.md`. `show --open` не прячет
  открытые узлы под закрытыми родителями.
- Вход `exports` пакета указывал на несуществующий `dist/index.js`; теперь файл на месте.
- Brainyard теперь `^0.3.3`.

## Удаление

`treeyard uninstall` убирает всё, что treeyard положил вне `.tree/`: скиллы, хук коммитов,
хуки писем и плагин OpenCode, драйвер слияния. `--settings` убирает и `~/.treeyard`,
`--dry-run` только показывает, что уйдёт.

## Как обновиться

```sh
npm install -g @antondanv/treeyard@latest   # или то же через pnpm, yarn или bun
treeyard --version                          # 0.2.0
```

Node.js 22+ и tmux (для панелей) — как раньше. Деревья переносить не нужно. Что изменится при
первом запуске:

1. **Скиллы ставятся сами.** Первый `treeyard` в папке с деревом кладёт скиллы в
   `~/.claude/skills`, `~/.codex/skills` и `~/.gemini/config/skills`. Хочешь руками —
   `treeyard config skills off`, а потом `treeyard skills install`, когда нужно.
2. **Блок в AGENTS.md стал короче.** Шапка TUI скажет, что он устарел: нажми `!` или запусти
   `treeyard pointer` и закоммить правку.
3. **Старые «Правила для агентов» уходят.** В деревьях из 0.1 в `.tree/tree.md` лежат правила
   шаблона, которые теперь держит скилл, и они с ним спорят («сначала план»,
   `set status=review`). Шапка TUI скажет «правила для агентов устарели»: `!` уберёт их
   заодно с блоком, из shell — `treeyard rules --upgrade`. Свои строки и правила метода
   останутся. Закоммить `.tree/tree.md`.
4. **Появится `.tree/.gitattributes`** при первой записи в дерево (драйвер слияния обзора).
   Закоммить его вместе с деревом, например `treeyard commit`.
5. **По желанию:** `treeyard hook install` (коммиты сами привязываются к узлам) и
   `treeyard hook claude install` (или `codex`, `antigravity`, `opencode`) для писем посреди
   хода. Уже открытой сессии может понадобиться перезапуск, чтобы подхватить хук.
6. **Проверка:** `treeyard status` покажет, что настроено и что поправить.

Полный справочник: [docs/reference.ru.md](reference.ru.md).
