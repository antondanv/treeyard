# Как устроен treeyard

```
.tree/tree.md, .tree/nodes/*.md  ←→  model  ←→  cli (команды)  ─┐
        (md + YAML, в git)                  ←→  tui (Ink)        ├→ agents → Brainyard → claude / codex / agy / opencode
                                                                 ┘                     └→ tmux -L brainyard (панели)
```

## Данные — `src/model/`

Дерево живёт в самом проекте, в `.tree/`: `tree.md` — корень (цель, метод, правила для
агентов, «Решения»), `nodes/<id>.md` — узел: YAML-шапка (статус, кто, «готово, когда»,
проверка, ждёт/до, связи с другими проектами `needs`/`for`, сессии, `commits` — SHA коммитов узла)
и тело, последний раздел которого — журнал.

- `store.ts` — чтение и запись; каждая запись — через временный файл и rename, агент
  никогда не видит половину файла.
- `ops.ts` — все изменения дерева; после каждого пересобирается `.tree/README.md`
  (`overview.ts`) — всё дерево одной страницей для GitHub и агентов.
- `tree.ts` — вопросы без изменений: прогресс, «сейчас», «ждёт»; `journal.ts`,
  `activity.ts` — журнал узла и общая лента.
- `queue.ts` — `treeyard queue`: очередь узлов по порядку среди братьев и `needs`, не больше
  `--parallel` сессий и `max_panes`, следующий — по `look()` из `wait.ts`, пауза по окнам подписки
  из `usage()` Brainyard; повторный запуск подхватывает узлы в работе.
- `mail.ts` — письма `treeyard send`: записи в журналах обоих узлов («письмо №12 от «A»», «письмо
  №12 узлу «B»», старые строки без номера тоже), их разбор на обоих языках, `mailOf` — письма узла с
  текстом и статусом из ящика для `show --only mail` и раздела «Письма» в TUI, `senderNode` — узел
  сессии, которая пишет или открывает другую.
- `mailbox.ts` — ящик писем проекта в `.tree/.local/mail/` (не в git): файл на письмо, номер берётся
  созданием файла (`wx`), статус «в очереди» (и почему) или «доставлено» (как); замок одной доставки
  `.lock` и файл доставщика `.deliverer` с pid.
- `notes.ts` — `treeyard note`: замечание из любого проекта в «Замечания» дерева из
  настройки `notes`, с проектом и узлом, откуда оно пришло.
- `links.ts` — связи между деревьями разных проектов: `needs` (ждёт узла там) и `for`
  (нужен для узла там), путь от папки проекта; «Совместные узлы», автозакрытие, чтение
  чужого дерева с кэшем по времени файлов, «не найдено» без падения.
- `../github.ts` — доска GitHub Project и issues репозитория через `gh`: `github:` в `tree.md` —
  доска и колонки статусов, `repo`; в узле — его карточка и колонка, где она была при последнем
  согласии, и issue с её состоянием (open/closed/gone) тогда же. `syncBoard`/`syncIssues` —
  в обе стороны; смена статуса в процессе двигает карточку и закрывает/открывает issue через `onStatusChange` из `ops.ts`
  (подписываются CLI и TUI, тесты — нет). Пока ничего не подключено, `tui/tree-view.ts` показывает в корне
  узел-предложение «GitHub» (не файл); `tui/github-connect.tsx` — мастер: gh → репозиторий → доска,
  создать самому или агентом (узел и сессия под настоящим узлом `github: hub`). Подключены
  только issues — предложение (`boardOffered`) живёт на настоящем узле: `⏎`/`G` спрашивают
  «свериться или подключить доску» (`GithubChoice`), второе — мастер сразу на шаге доски.
- `images.ts` — картинки узла в `.tree/.local/images/<id>/` (PNG + `index.json` с
  подписями, не в git); после «готово», «отказ» или удаления узла — ещё неделя, потом
  `purgeImages` (при запуске TUI и CLI). `clipboard.ts` — картинка из буфера
  (`osascript` на Mac, `wl-paste`/`xclip`).
- `.tree/.local/` — вид и выбранный узел конкретного человека, не в git.
- `../git.ts` — чтение Git для CLI и TUI: отдельные дифы явно связанных коммитов,
  файлы и статистика, общие staged/unstaged/untracked. Команды просмотра не меняют индекс или историю.
- `../docs.ts` — документы проекта для корня: `.md` из Git (отслеживаемые и новые, без
  игнорируемых и узлов дерева; без Git — обход папки) с заголовками, чтение и запись с
  сохранением CRLF; `tree.md` с битой YAML-шапкой не пишется. Один список для окна `P` и
  `treeyard docs`.
- `../projects.ts` — папки с деревьями, которые видел treeyard, в `~/.treeyard/projects.json`:
  `projectDir()` в CLI и `runTui` запоминают папку (не чаще раза в 10 минут, без связанных
  git worktree), `treeyard projects` перечисляет те, где дерево ещё есть.

## Входы

- `src/cli/` — `treeyard <команда>`: show, add, set, log, note, open, sessions, wait, send, import,
  status, pointer, skills, config, github, docs, projects. Те же команды, что у человека, используют агенты.
- `src/status.ts` + `cli/status-text.ts` — `treeyard status`: папка и дерево (из git worktree —
  основное), узлы, скиллы, указатель, хук, живые сессии и панели, GitHub; у каждой проблемы —
  команда-исправление. Только читает; CLI, tmux и `gh` подставляются в тестах.
- `src/watch.ts` — `treeyard watch`: снимок файлов `.tree/`, сравнение двух снимков (не больше
  одного события на узел) и слежение — `fs.watch` с запасным опросом времён файлов; читает,
  когда файлы затихли, поэтому пачка правок даёт одно событие на узел. Только читает.
- `src/tui/` — интерфейс: `App.tsx` (всё состояние и клавиши), `graph.tsx` и `rows.tsx`
  (граф и списки), `details.tsx`, `dialogs.tsx`, `terminal.tsx` (живая панель сессии),
  `image-view.tsx` (картинка символами `▀`: цвет текста — верхний пиксель, фон — нижний; кэш декода), `images-dialog.tsx` (окно `I`), `init.tsx` (мастер посадки), `run.tsx` (уступить терминал CLI и вернуться),
  `diffs-dialog.tsx` (окно `V`: коммиты узла → файлы → диф, выбор коммитов из Git-журнала),
  `docs-dialog.tsx` (окно `P` с корня: документы → чтение → правка), `markdown.ts` (разметка
  в цветные строки, заранее перенесённые по ширине; у строки — номер исходной), `doc-editor.tsx`
  (встроенный редактор: перенос по строкам с кэшем, отмена по словам, `⌃S` не затирает файл,
  изменившийся на диске),
  `history.ts` (отмена, не откатывающая правки агента), `mouse.tsx` (клики: один
  слушатель находит самый вложенный бокс под указателем; клик по подсказке нажимает
  её клавишу через `TerminalInput.press`, поэтому мышь не делает ничего сверх клавиатуры).

## Агенты — `src/agents/`

Всё общение с CLI — через Brainyard.

- `launch.ts` — сессия из узла или корня (`root`); узел запоминает её id,
  сессия получает `TREEYARD_NODE=<id>`. Проектные сессии хранятся в `tree.md`;
  `holderOf`/`sessionHolders` включают корень в списки и жизненный цикл панелей.
  `context.ts` для узла собирает путь от корня, критерий, соседей, правила и команды;
  для корня — обзор дерева, «Сейчас», «Ждёт», журналы и правила. Ревью выдаёт находки
  до согласия, разговор начинается сообщением человека.
- `panes.ts`, `pane-idle.ts` — сессии в панелях tmux: запуск, сон и пробуждение,
  автосон только при положительном подтверждении простоя, лимит живых панелей;
  `sessionPanes` — панель каждой сессии для `sessions --json` (только чтение).
- `wait.ts`, `send.ts` — координатор ведёт розданные узлы: `treeyard wait` ждёт, пока узел уйдёт
  из «в работе» или его сессия закончит ход, станет ждать человека или закончится (дерево — по
  `watch.ts`, сессии — `liveSessions` и панели Brainyard); `treeyard send` пишет следующую реплику
  той же сессии: письмо — в ящик, затем `deliver.ts`.
- `deliver.ts` — доставка ящика: `routeOf` решает по состоянию сессии — свободной панели вставкой и
  Enter, уснувшей — `--resume` в новой панели, фоновой Claude Code после хода — остановкой и
  `--resume --bg`; занятой, ждущей человека, открытой в терминале и узлу без сессии — ждать.
  `runDeliverer` — `treeyard deliver`, один на проект, отдельный процесс от `send` (`spawnDeliverer`),
  проходы раз в 3 с, пока есть что доставить; `ensureDeliverer` перезапускает его из `send`, `wait` и
  TUI. Новая сессия узла получает ждущие письма в первом сообщении (`sessionPlan` → `letters`).
- `skills.ts` — скиллы из `skills/` (`treeyard`, `treeyard-init`, `treeyard-coordinate`): где их ищет каждый CLI (свой
  дом и папка проекта), стоит ли свежая копия, установка папкой целиком; `autoInstallSkills` — сама
  при каждой команде в папке с деревом (в дома CLI, настройка `skills`).
- `planting.ts` + `skills/treeyard-init` — посадка дерева с агентом; `importer.ts` —
  перенос старого плана и `import --from-json`.
- `assist.ts` — короткие задачи без сессии (разбить на шаги, критерий); `check.ts` —
  команда проверки узла.

## Остальное

- `src/templates/` + `templates/*.yaml` (`en/` — английские) — шаблоны посадки;
  `pointer.ts` — блок о дереве в AGENTS.md / CLAUDE.md.
- `src/i18n/` — русский текст как ключ, `en.ts` — словарь, по умолчанию — английский;
  `src/settings.ts` — `~/.treeyard/settings.json`, настройки проекта — в `.tree/tree.md`.
