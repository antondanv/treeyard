# Как устроен treeyard

```
.tree/tree.md, .tree/nodes/*.md  ←→  model  ←→  cli (команды)  ─┐
        (md + YAML, в git)                  ←→  tui (Ink)        ├→ agents → Brainyard → claude / codex / agy
                                                                 ┘                     └→ tmux -L brainyard (панели)
```

## Данные — `src/model/`

Дерево живёт в самом проекте, в `.tree/`: `tree.md` — корень (цель, метод, правила для
агентов, «Решения»), `nodes/<id>.md` — узел: YAML-шапка (статус, кто, «готово, когда»,
проверка, ждёт/до, связи с другими проектами `needs`/`for`, сессии) и тело, последний раздел которого — журнал.

- `store.ts` — чтение и запись; каждая запись — через временный файл и rename, агент
  никогда не видит половину файла.
- `ops.ts` — все изменения дерева; после каждого пересобирается `.tree/README.md`
  (`overview.ts`) — всё дерево одной страницей для GitHub и агентов.
- `tree.ts` — вопросы без изменений: прогресс, «сейчас», «ждёт»; `journal.ts`,
  `activity.ts` — журнал узла и общая лента.
- `notes.ts` — `treeyard note`: замечание из любого проекта в «Замечания» дерева из
  настройки `notes`, с проектом и узлом, откуда оно пришло.
- `links.ts` — связи между деревьями разных проектов: `needs` (ждёт узла там) и `for`
  (нужен для узла там), путь от папки проекта; «Совместные узлы», автозакрытие, чтение
  чужого дерева с кэшем по времени файлов, «не найдено» без падения.
- `../github.ts` — доска GitHub Project через `gh`: `github:` в `tree.md` — доска и колонки
  статусов, в узле — его карточка и колонка, где она была при последнем согласии. `sync` —
  в обе стороны; смена статуса в процессе двигает карточку через `onStatusChange` из `ops.ts`
  (подписываются CLI и TUI, тесты — нет).
- `.tree/.local/` — вид и выбранный узел конкретного человека, не в git.

## Входы

- `src/cli/` — `treeyard <команда>`: show, add, set, log, note, open, sessions, import,
  pointer, skills, config, github. Те же команды, что у человека, используют агенты.
- `src/tui/` — интерфейс: `App.tsx` (всё состояние и клавиши), `graph.tsx` и `rows.tsx`
  (граф и списки), `details.tsx`, `dialogs.tsx`, `terminal.tsx` (живая панель сессии),
  `init.tsx` (мастер посадки), `run.tsx` (уступить терминал CLI и вернуться),
  `history.ts` (отмена, не откатывающая правки агента), `mouse.tsx` (клики: один
  слушатель находит самый вложенный бокс под указателем; клик по подсказке нажимает
  её клавишу через `TerminalInput.press`, поэтому мышь не делает ничего сверх клавиатуры).

## Агенты — `src/agents/`

Всё общение с CLI — через Brainyard.

- `launch.ts` — сессия из узла; узел запоминает её id, а сессия получает
  `TREEYARD_NODE=<id>`. `context.ts` — первое сообщение:
  путь от корня, критерий, соседи, правила, команды дерева.
- `panes.ts`, `pane-idle.ts` — сессии в панелях tmux: запуск, сон и пробуждение,
  автосон только при положительном подтверждении простоя, лимит живых панелей.
- `planting.ts` + `skills/treeyard-init` — посадка дерева с агентом; `importer.ts` —
  перенос старого плана и `import --from-json`.
- `assist.ts` — короткие задачи без сессии (разбить на шаги, критерий); `check.ts` —
  команда проверки узла.

## Остальное

- `src/templates/` + `templates/*.yaml` (`en/` — английские) — шаблоны посадки;
  `pointer.ts` — блок о дереве в AGENTS.md / CLAUDE.md.
- `src/i18n/` — русский текст как ключ, `en.ts` — словарь; `src/settings.ts` —
  `~/.treeyard/settings.json`, настройки проекта — в `.tree/tree.md`.
